Channel Architecture

Four independent channels, one shared agent brain
💬
Web Chat
Real-time bidirectional WebSocket with streaming token delivery. HTTP fallback for environments that block WS.
  • WebSocket: /chat/ws/{tenant}/{customer}
  • HTTP fallback: POST /chat/message
  • Two-frame response (message → done + latency)
  • Session state across browser refresh
  • JWT token auth per tenant
📞
Voice / Twilio
Twilio TwiML webhooks drive inbound call handling. AI generates TwiML response to speak back to the caller.
  • TwiML webhook: POST /api/twilio/voice
  • Voice-specific short prompts (< 2 sentences)
  • Conversational, no bullet points
  • IVR fallback for complex issues
  • Webhook signature validation
📧
Email
Polls Gmail IMAP inbox every 60 seconds, processes unread support emails, and auto-replies via SMTP.
  • Gmail IMAP polling (async with executor)
  • Email-specific prompt: formal, structured
  • Full paragraphs with proper formatting
  • Thread context preserved
  • Escalation → creates draft for human
🔀
n8n Automation
n8n sits alongside the agent as an automation layer — receives escalation webhooks and drives downstream integrations.
  • Receives escalation events via webhook
  • Routes to Slack / email / Zendesk
  • Calls back to POST /n8n/ticket-resolved
  • Can trigger KB re-ingestion from Drive
  • Visual workflow editor at :5678

Request Processing Pipeline

Step-by-step trace of a chat message through the system
1
Customer sends message
WebSocket frame arrives at POST /chat/message or /chat/ws/{tenant_id}/{customer_id}. FastAPI validates the Pydantic ChatRequest schema. JWT token is verified against tenant record.
2
Session loaded / created
SessionService.get_or_create() looks up ConversationSession in SQLite. Last 20 messages pulled as HumanMessage / AIMessage objects for the LLM context window.
3
LangGraph ReAct loop starts
create_react_agent(llm, tools) receives the message + history. LLM decides: should it call search_knowledge_base, call escalate_to_human, or respond directly? Repeats up to 4 iterations.
4
RAG retrieval (if tool called)
search_knowledge_base(query) calls retrieve(query, tenant_id). ChromaDB performs cosine similarity search on the tenant-isolated collection (tenant_{id}). Returns top-4 chunks via MMR (Max Marginal Relevance) to avoid duplicates. Chunks are appended as a ToolMessage for the next LLM iteration.
5
LLM generates final response
With KB context available, Groq (llama-3.3-70b-versatile) generates the answer, grounded strictly in retrieved content. Temperature = 0.1 for consistency. Channel-specific prompt (voice: <2 sentences · email: full paragraphs).
6
Escalation safety net runs
Layer 1 (LLM-driven): LLM may call escalate_to_human(reason, urgency) mid-loop. Layer 2 (Rule-based safety net): EscalationEngine checks regex patterns (fire, smoke, legal, "speak to human") on the user's message after the LLM responds. Either layer can trigger escalation independently.
7
n8n webhook fired (on escalation)
asyncio.create_task(n8n_client.notify_escalation(...)) fires a non-blocking POST to http://n8n:5678/webhook/ai-agent-escalation. n8n workflow routes based on urgency: high → #support-urgent Slack + email · normal → #support-queue Slack. Agent never waits for n8n — escalation succeeds even if n8n is down.
8
Response streamed + session saved
Chat: two WebSocket frames — {type:"message", content:"..."} then {type:"done", escalated:false, latency_ms:1240}. Message persisted to SQLite. structlog writes JSON line with tenant_id, session_id, latency.

Multi-Tenant Data Isolation

Four independent layers prevent any cross-tenant data leakage
Tenant A
Acme Corp
ChromaDB: tenant_acme
JWT: scope=acme
SQLite: tenant_id=acme
Tenant B
Globex Inc
ChromaDB: tenant_globex
JWT: scope=globex
SQLite: tenant_id=globex
Tenant C
Umbrella
ChromaDB: tenant_umbrella
JWT: scope=umbrella
SQLite: tenant_id=umbrella
4-Layer Isolation Architecture
Layer 1 — ChromaDB Collection
Each tenant has a dedicated vector collection. Cross-collection queries are architecturally impossible.
Layer 2 — Python Closure Lock
tenant_id is closed over in the tool function at agent creation time. The LLM cannot override it.
Layer 3 — SQL Filter
All SQLite queries include WHERE tenant_id = ?. No bare SELECT without tenant context.
Layer 4 — JWT Validation
API key validated against tenant record before request handling begins.
Closure-Based Tool Isolation Pattern
# tenant_id is BAKED IN at agent-creation time
# The LLM receives the tool but CANNOT change tenant_id

def make_search_tool(tenant_id: str):

    @tool
    async def search_knowledge_base(query: str) -> str:
        """Search the company knowledge base."""
        results = await retrieve(
            query=query,
            tenant_id=tenant_id  # ← CLOSED OVER — immutable
        )
        return format_results(results)

    return search_knowledge_base

# Agent created per-request with tenant context locked
agent = create_react_agent(
    llm=llm,
    tools=[make_search_tool(tenant_id)]  # ← locked at creation
)

Key Architectural Features

Design decisions that matter in production
🔄
LangGraph ReAct (Not One-Shot)
The agent iterates up to 4 turns per message. It decides whether to search the KB, call a tool, or respond directly. A simple greeting doesn't trigger unnecessary KB queries — the agent knows when to skip retrieval.
LangGraph Tool Calling Efficiency
🛡️
Dual Escalation System
Layer 1: LLM uses escalate_to_human tool mid-reasoning for complex issues. Layer 2: Safety regex runs after LLM responds — catches keywords like "fire", "smoke", "legal" that must always escalate regardless of LLM decision.
Safety-Critical Rules + LLM Defense-in-Depth
🎯
MMR Retrieval (No Duplicates)
ChromaDB uses Maximal Marginal Relevance (lambda=0.7) — balances relevance with diversity. Fetches 20 candidates, returns top 4 that are both relevant AND non-redundant. LLM context stays clean.
ChromaDB MMR RAG Quality
⚡
WebSocket Two-Frame Protocol
Chat responses use two frames: {type:"message", content:"..."} then {type:"done", escalated:false, latency_ms:1240}. UI can render the message immediately while metadata (latency, escalation flag) arrives asynchronously.
WebSocket Low Latency Streaming
🔀
n8n as Automation Backbone
n8n receives escalation webhooks and drives Slack/email/Zendesk routing without code changes. Adding a new integration (PagerDuty, Jira, Teams) requires only a new n8n workflow — zero Python changes. Failure-tolerant: agent escalation succeeds even if n8n is unreachable.
n8n No-Code Integrations Fault-Tolerant
💰
Free-Tier First Design
Groq free tier (llama-3.3-70b), ChromaDB local, SQLite, MiniLM embeddings (CPU), n8n self-hosted. Production-ready architecture with zero cloud cost during development. Swap to Pinecone + OpenAI when ready.
Groq ChromaDB $0 Dev Cost
